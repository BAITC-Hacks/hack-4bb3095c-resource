# Сценарий демо (3 минуты)

Формула: боль → одна кнопка → доказательство на их данных → решение за собственником.
Цифры в скобках — подставлять из вкладки «Машина времени» / README (они генерируются из data/results).

## 0:00–0:25 — Боль (говорим, экран: первый экран сервиса)
«Менеджер закупа Электрокомплекта ведёт 3 600 артикулов двух поставщиков в Excel. Полдня на заказ — поэтому
считают редко. Итог в их же данных: за полгода [N] раз товар отсутствовал на складе на начало месяца,
а [X] млн ₸ лежит в излишках. И одна крупная разовая продажа ломает весь расчёт».

## 0:25–1:10 — Одна кнопка (экран: «Заказ поставщикам», режим «Требует решения сейчас»)
- «Сервис уже посчитал заказ по всем артикулам. Сверху — только то, что требует решения сегодня».
- Навести на строку: мини-график спроса, шкала риска, «Обоснование» — прочитать одну фразу вслух.
- Изменить «К заказу» в одной строке → ввести ФИО в поле «Кто утверждает (ФИО)» → нажать «Утвердить заказ» или «Выгрузить заказ для 1С (Excel)».
- «Автоотправки нет — решение всегда за человеком».

## 1:10–1:40 — Почему столько (экран: «Разбор артикула» или «AI-ассистент»)
- Разбор: график, красные месяцы без товара, исключённые разовые заказы — «вот этот клиент купил 30 000 шт разово —
  Excel бы решил, что спрос вырос. Мы — нет».
- Ассистент: кнопка «Что критично по IEK прямо сейчас?» — ответ только по данным, с кодами 1С.

## 1:40–2:30 — Доказательство (экран: «Машина времени»)
- «История одного товара: как было и как было бы с сервисом»: «вот товар — у вас [4] месяца было пусто. С сервисом — ни разу».
- «Кривая выбора: сколько стоит каждый процент сервиса»: красный ромб — как было. «При сервисе 80% — меньше дефицитов И меньше денег на складе одновременно.
  Каждый процент сервиса имеет цену в тенге — и выбирает её собственник, а не Excel».

## 2:30–3:00 — Масштаб и финал
- «Данные и параметры» → выбрать «Загрузить свой файл» → «Скачать шаблон (пример)»: любая компания на 1С — пилот за день, без интеграций.
- Финальная фраза: «Не прогноз ради прогноза, а заказ, которому можно доверять: каждая строка объяснена,
  результат проверен на вашей же истории».

## Ответы на вероятные вопросы жюри
- *Точность прогноза?* — Проверили честно на отложенных месяцах: на уровне «среднего за 12 мес.» (WAPE ~32–36%);
  помесячный спрос по артикулу шумный, поэтому выигрыш даёт политика заказа, а не «магия прогноза».
- *Почему не ML?* — Объяснимость и устойчивость к выбросам — требования ТЗ; каждую строку менеджер может проверить.
- *Нет сроков поставки в данных?* — Справочник в UI (оценка по документам «в пути»), меняется за секунду.
- *Что с данными клиентов?* — В выгрузке их нет; поле client поддерживается обезличенным.
