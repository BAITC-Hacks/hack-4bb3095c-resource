# План масштабирования «Автозаказ ЕКТ»

Стратегия — «кегли» (bowling pin): захватить маленький плотный сегмент, где продукт незаменим, и расширяться в соседние,
переиспользуя то, что уже работает. Так росли Facebook (Гарвард в 2004 → другие университеты Лиги плюща и Бостона →
все университеты → школы → все пользователи в 2006), Amazon (книги → всё остальное), Toast (софт для ресторанов →
платежи и финансирование для тех же ресторанов). Общий принцип: **сначала стать №1 для одного клиента с одной болью**
(метод «5 единичек»), затем добавлять клиентов, затем — новые продукты для тех же клиентов.

Цифры рынка ниже не приводятся без проверки: каждое допущение помечено как гипотеза для пилота.

## Кегля 1 — «Гарвард»: Электрокомплект (0–3 месяца)
- **Кто:** один дистрибьютор, два поставщика (IEK, Systeme Electric), менеджер закупа.
- **Что уже есть:** расчёт заказа, очередь решений, симулятор склада, бэктест на их истории, выгрузка в 1С.
- **Цель пилота:** еженедельный заказ целиком через сервис; метрики — случаи «нет на складе», запас в ₸,
  время на заказ. Бэктест уже показывает −54% / −72% дефицитов — пилот подтверждает это вживую.
- **Что доделать:** все поставщики и склады компании; сроки поставки из фактических документов; выгрузка по расписанию.

## Кегля 2 — «Лига плюща»: другие дистрибьюторы электротехники в Казахстане (3–12 месяцев)
- **Почему именно они:** тот же ассортимент, те же поставщики (IEK, Systeme Electric и др.), та же учётная система
  (1С), та же боль. Продукт переносится почти без доработок — загрузка своих данных по шаблону уже работает.
- **Канал (одна единичка):** рекомендация поставщика. IEK и Systeme Electric заинтересованы, чтобы их товар не
  отсутствовал на полках дилеров, — они приводят дистрибьюторов (гипотеза: проверить интерес поставщиков).
- **Конвертер (одна единичка):** бесплатный бэктест «Машина времени» на выгрузке клиента: «вот сколько раз за полгода
  у вас не было товара и сколько денег лежит в излишках». Решение о покупке — после цифр на своих данных.
- **Модель:** подписка за склад / за число активных артикулов (гипотеза цены — проверить на пилотах).

## Кегля 3 — «Все университеты»: соседние отрасли дистрибуции (1–2 года)
Та же задача «склад + поставщики + сезонность + разовые крупные заказы» есть в:
- стройматериалах и сантехнике (сильная сезонность, проектные крупные заказы — наш алгоритм разовых заказов);
- автозапчастях (длинный хвост артикулов, ABC, редкие продажи);
- FMCG и продуктовой дистрибуции (акции, короткие сроки);
- аптечных сетях (страховой запас критичен, дефицит недопустим).
Что меняется: отраслевые шаблоны загрузки, свои правила (сроки годности, акции). Ядро расчёта — общее.

## Кегля 4 — «Весь мир»: Центральная Азия (2–3 года)
Узбекистан, Кыргызстан — те же поставщики, 1С и русскоязычные интерфейсы; добавляются казахский, узбекский и
английский языки интерфейса и ассистента.

## Второй двигатель: новые продукты для тех же клиентов (как Toast)
1. **Сотрудничество с поставщиками (collaborative forecasting).** Дистрибьютор делится прогнозом заказов с IEK / SE —
   поставщик планирует производство и логистику. Платит поставщик: он получает видимость спроса по всей дилерской сети.
2. **Финансирование закупки.** Рекомендованный заказ — готовая заявка на оборотный кредит или рассрочку у банка-партнёра:
   сервис видит обоснованную потребность и историю оборачиваемости (гипотеза: партнёрство с банками экосистемы хакатона).
3. **Биржа излишков.** Излишки одного дистрибьютора — дефицит другого: вкладка «Излишки» уже считает, что лежит лишнего;
   следующий шаг — предложить это другим участникам сети.
4. **Бенчмарки отрасли.** Обезличенные сезонные профили и уровень сервиса по отрасли: «у похожих компаний дефицит
   в 2 раза ниже — вот за счёт чего». Каждая новая компания улучшает сезонные профили для всех — сетевой эффект данных.
5. **Автопилот закупки.** AI-агент ежедневно готовит заказ и письма поставщикам; человек утверждает одной кнопкой.
   Уровень автоматизации растёт вместе с доверием, измеренным по аудиту правок.

## Защитный ров (почему нас трудно повторить)
- **Данные и доверие:** бэктест на истории клиента до покупки — продажа результатом, а не обещанием.
- **Аудит правок:** причины правок менеджеров — уникальный датасет, на котором система учится (п. 3 развития в README).
- **Сетевой эффект:** поставщики, банки и дистрибьюторы в одной сети ценят сервис тем больше, чем больше в ней участников.
- **Внедрение за день:** Excel из 1С → результат, без ИТ-проекта; большие системы планирования требуют интеграции.

## Что проверить в первую очередь (гипотезы)
| Гипотеза | Как проверить | Критерий успеха |
|---|---|---|
| Менеджер доверяет рекомендациям | 4 недели пилота в ЕКТ, доля строк без правок | > 80% строк утверждаются без изменений |
| Бэктест подтверждается вживую | Пилот: случаи «нет на складе» до/после | снижение, сопоставимое с бэктестом |
| Поставщики готовы приводить дилеров | Разговор с IEK / Systeme Electric | согласие на совместный пилот |
| Компании платят за результат | 3 бесплатных бэктеста у других дистрибьюторов | ≥ 1 платный пилот |
