## Жёсткие правила (нарушение = дисквалификация / недопуск)
1. Вся разработка — только в этом репозитории. Коммит + push минимум раз в час (лучше каждые 20–30 мин).
2. Основная функциональность пишется во время хакатона. Заготовки/инфраструктура допустимы, но раскрываются в README.
3. Любой сторонний код, модель, датасет, библиотека — указать в README (раздел «Данные и интеграции»).
4. Проект ОБЯЗАН запускаться по README на чистой машине. Не запустился — команда снимается, исправления не принимаются.
5. Проверка без личных аккаунтов: должен быть DEMO-режим (`DEMO_MODE=1`) с заранее сохранёнными ответами, если ключей нет.
6. Никогда не коммитить ключи. Секреты — только в `.env` (в .gitignore). В репо — `.env.example`.

## Как писать код
- Один главный сценарий «вход → результат» работает end-to-end раньше любых «фич».
- Сначала требования и критерии кейса (ТЗ задачи), потом всё остальное. Каждая фича = пункт рубрики.
- Python ≥3.11 совместимость (у жюри может быть не 3.14). Зависимости — в requirements.txt с версиями.
- Одна команда запуска (`./run.sh` или `make run`), описана в README.
- Внешние API обёрнуты: таймаут, повтор, фолбэк (OpenAI → NVIDIA Build → demo-кэш).
- Не выдумывать в README функции, которых нет.
